2. TYPICAL COMBINED LOG FORMAT ANATOMY IDENTIFIED
--------------------------------------------------------------------------------
A typical Apache/Nginx Combined Log Format line adheres to the 9-tuple schema:
  %h %l %u %t "%r" %>s %b "%{Referer}i" "%{User-Agent}i"

Token Breakdown:
  1. %h (Client IP)       : Remote IP address initiating the connection.
  2. %l (Client Ident)    : RFC 1413 identity of the client (usually '-').
  3. %u (User ID)         : HTTP Basic Auth authenticated user (usually '-').
  4. %t (Timestamp)       : Date and time of request [DD/Mon/YYYY:HH:MM:SS +TZ].
  5. %r (Request Line)    : Method, Resource URI, and HTTP protocol.
  6. %>s (Status Code)    : Final 3-digit HTTP response code from server.
  7. %b (Bytes Sent)      : Size of response object excluding headers.
  8. Referer Header       : Originating URL referring the client to this resource.
  9. User-Agent Header    : Browser, operating system, or bot identification.

4. USEFUL FIELDS IDENTIFIED FOR ADVANCED ANALYSIS
--------------------------------------------------------------------------------
  * Resource URI & Payload: Critical for detecting SQLi, XSS, Path Traversal, and LFI.
  * Client IP & Timestamp : Essential for calculating inter-request timing, IP velocity,
                            burst ratios, and identifying DDoS / Brute Force attacks.

                            404 (Directory Fuzzing), and 503/429 (DDoS Floods).
  * User-Agent Header     : Discriminates legitimate browsers from automated scanners
